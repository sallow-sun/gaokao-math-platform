# 用户成长系统（测试版）

## 入口与规则

个人主页昵称旁显示 Lv.0–Lv.6。自己的学习统计页显示经验进度、公开规则与分页明细。他人只能看到等级。负责人在管理后台“用户管理 → 等级与经验管理”可按数字用户 ID 查询明细并撤回不当经验，必须填写原因，操作写入审计日志。

集中配置文件：`backend/src/main/resources/growth-rules.json`。测试期可修改阈值、奖励和每日上限，更新 version 后重新部署。历史经验以流水中的实际数值为准，不按新奖励追溯重算；等级按当前阈值计算。阈值必须递增且首项为 0，共 7 项。规则不是权限来源，不影响审核权限或基础功能。

当前阈值：0、20、80、200、500、1200、3000。
- 首次标记新题已做：每题 1 点，每日上限 10 点。
- 当日首次上述学习：额外 2 点。
- 社区投稿首次通过他人审核：20 点，每日上限 100 点。管理员导入文件不自动奖励；同一作者相同规范化题干摘要只奖励一次。
- 纠错被他人采纳：10 点，每日上限 50 点。同一账号对同一题目只奖励一次。
- 收藏、浏览、登录和发布试卷暂不奖励。超出额度的事件记录为 0，不因以后重复操作而补发。
- 不因不活跃扣分。撤回不当经验可能导致降级；撤回原因对本人可见。

## 数据与一致性

V16 新增 user_growth_events。迁移时将已有 completed 标记记录为零分 BASELINE，防止取消后重新标记获取旧题经验。BASELINE 不展示在个人明细中。历史贡献不补发；上线后新完成的审核可按当前规则奖励。

奖励与原操作处于同一数据库事务。以用户行锁串行处理同一账号的经验写入，唯一 event_key 防重复；学习操作先锁用户再更新题目状态，避免批量标记锁顺序反转。每日额度按上海时区自然日计算。撤回是唯一关联原事件的负数流水，不删除原记录，也不恢复当天奖励额度。

接口：
- GET /api/v1/users/me/growth?page=1：仅本人经验、规则、等级和明细。
- GET /api/v1/users/{id}：现有公开资料增加 level，不公开经验流水。
- GET /api/v1/admin/growth/users/{id}?page=1：仅负责人查询。
- POST /api/v1/admin/growth/events/{id}/revoke：负责人、CSRF，body 为 reason；重复请求不重复扣分。
